As contagens são da árvore de dependências, incluindo ferramentas e dependências transitivas; não são contagem de falhas exploráveis no site estático. Pacotes de build/CLI não são publicados pelo script de agregação. Por outro lado, um scan sem segredos e testes de UI não comprovam ausência de vulnerabilidades em runtime. A classificação de publicação fica **com ressalvas de segurança**, aguardando triagem/correção compatível e aceite gerencial.

Prioridades concretas:

1. `@react-navigation/core` e sua cadeia, presentes nos apps: avaliar os avisos altos e atualizar os patches compatíveis com Navigation 7, repetindo rotas/deep links e mobile. `fixAvailable: true` no audit não certifica preservação do SDK.
2. `shell-quote` e `tar`: achados críticos na árvore de ferramentas. Revisar os caminhos de dependência e patches de cada SDK; manter servidores de desenvolvimento restritos a localhost e não publicar ferramentas.
3. ZooKids: `@react-native-community/cli` é uma dependência direta de desenvolvimento com achado crítico; avaliar atualização ou necessidade real no projeto Expo antes de mudar o manifesto. Não foi removida arbitrariamente.
4. MedLive: `axios` é uma dependência direta com achados altos; revisar versão e usos mobile/backend. A demo web resolve serviços fictícios em adapters `.web.js` e não executou chamadas HTTP de saúde nos testes; isso não libera o backend ou mobile real.
5. Horóscopo: Expo/CLI e cadeias antigas têm avisos que sugerem mudança principal de SDK. Não foi seguida essa recomendação automática, pois a OS exige preservar compatibilidade e o app ainda está bloqueado por assets.

A próxima correção deve ser incremental por aplicativo: identificar a cadeia, escolher versão compatível, instalação limpa, audit novamente e repetir web/mobile aplicável. Mudança estrutural de SDK deve ser uma decisão explícita; não foi feita apenas para zerar o relatório. Consulte a [documentação npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/).

## Chaves, endpoints e dados

- Duas configurações Google historicamente expostas no MedLive: chave Android Maps em `app.json` e chave Places em `src/principal/mapa/mapa.js`. Os literais foram removidos na OS-005; valores não são repetidos aqui. O proprietário deve restringir/rotacionar no provedor. Nenhuma tentativa de rotação foi executada.
- O endpoint HTTP privado no `crud.js` original é parte da implementação mobile preservada; o provider web fictício não o usa. Pacote web escaneado sem correspondência de endpoints internos, chaves conhecidas ou arquivos `.env`/PHP/fontes locais indevidas.
- `EXPO_PUBLIC_*` é configuração pública; não usar para segredo de servidor. Maps mobile requer configuração restrita, sem incorporar chaves reais nesta OS.
- Agenda e ZooKids usam cadastro acadêmico e senha local em texto simples. Não são autenticação segura. Usar apenas dados fictícios. Namespaces separados evitam que o logout ZooKids apague dados Agenda; teste de UI em mesmo origin cobre esse caso.
- MedLive usa perfil/credenciais fictícios em memória; foto é blob local. Recarregar restaura exemplos. Não houve cadastro real, token válido, upload ao Laravel ou serviço de saúde real.
- ViaCEP/frases/receitas do mobile e Google Places não foram validados para publicação real. O modo web fictício isola esses acessos; tiles e links externos dependem de ação explícita e não foram certificados como serviço de produção.

O pacote continua sem backend. Revisão de autorização por paciente, banco/CORS/HTTPS/arquivos permanece necessária antes de publicar o Laravel; ele não foi modificado nem iniciado.

Nenhum app recebe liberação pública irrestrita por ter compilado. As quatro demos funcionais podem seguir para avaliação/preview autorizado **com ressalvas**, incluindo a análise dos avisos de dependências. Horóscopo permanece bloqueado. Template é preservado, mas bloqueado na lista pública do produto completo.
